# Conferir o projeto atual antes de propor uma alteracao

Texto fixo e campo variavel sao diferentes. Escrever uma formula no texto fixo nao a transforma em calculo. Para calcular um valor, usar um campo de saida, inclusive quando ele estiver inserido em um texto.

Se a regra existe no desktop e nao aparece na web, conferir a regra geral da janela, a regra de impressao e a selecao dos detalhes separadamente. Cabecalho vazio nao deve receber o conteudo do primeiro detalhe. Uma janela pode ter varias definicoes de detalhe; isso nao significa repetir automaticamente a mesma linha.

Numeros da formula nao sao dados do cliente. Uma mascara nao deve inventar zeros a partir desses numeros. A confirmacao dos valores exige usar a massa de dados no preview.

Para localizar o item, identificar documento, nome, tipo e posicao. O mesmo nome pode existir em varios documentos. Em caso de ambiguidade, apresentar os candidatos e pedir qual e o alvo antes de editar.

Quando o arquivo ou o layout atual foi enviado, a assistente pode receber uma inspecao real e informar problemas encontrados. Quando nao foi enviado, ela orienta a verificacao e pede o arquivo ou documento necessario. Nao dizer que abriu, corrigiu, salvou ou criou algo apenas por conhecer o assunto.

Uma primeira pagina correta nao confirma as outras. Se o erro acontece ao avancar, conferir a pagina afetada e informar quais paginas foram testadas. Preview e PDF final sao verificacoes diferentes.

Imagens podem ser externas ao projeto legado. Icone de imagem substituta nao prova que o arquivo original foi importado. Informar recursos ausentes e conferir imagens dinamicas com os dados.

Consulta e diagnostico nao salvam o projeto. Para uma alteracao, separar pedido, alvo identificado, efeito esperado e verificacao posterior. Se so houve analise, dizer isso com clareza.
